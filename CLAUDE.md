# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

> This file is intentionally high-level. Implementation details, conventions, and the project todo list live in `README.md`.

## What this is

wiki-ai is a template for an AI-powered single-project research wiki. Each repo instance is one research project (e.g. "designing a game"). Claude Code is the primary interface — users invoke skills to research, report, lint, and maintain a graph of interlinked Markdown notes. A Python web server (FastAPI + D3.js) provides a browser UI with an Obsidian-style link graph, running in Docker.

Users start a new wiki with a single command — no forking:
```sh
curl -fsSL https://raw.githubusercontent.com/dennisdms/wiki-ai/main/scripts/init.sh | sh -s -- "my-project"
```

## Folder structure

```
_index.md          # Project home (auto-maintained)
sources/
  bibliography.md  # All external URLs — notes link here, never inline raw URLs
  assets/          # User-pasted source materials (PDFs, images, etc.)
content/           # Research notes, recursively organized with _index.md per folder
reports/           # Generated reports — never hand-edited
.claude/
  skills/          # One file per skill (research, report, lint, cleanup)
  agents/
scripts/           # All Python: FastAPI server, git sync, Dockerfile, static/, templates/
```

## Key invariants

- `[[wiki-links]]` are the connective tissue — every note links to related notes, bibliography entries (`[[bibliography#slug]]`), and assets (`[[assets/file]]`).
- `_index.md` files are recursive: every directory has one, auto-regenerated by the cleanup skill.
- `sources/bibliography.md` is the only place raw URLs live.
- `sources/assets/` is user-managed source material — paste files here directly.
- `reports/` are generated artifacts — regenerate, never patch.
- All Python (server, sync, Docker) lives in `scripts/`.

## Skills

| Skill | Purpose |
|---|---|
| `research` | Research a topic, save a note, update bibliography and indexes |
| `report` | Synthesize notes into a report in `reports/` |
| `lint` | Check link integrity, frontmatter, bibliography duplicates |
| `cleanup` | Fix lint issues, regenerate `_index.md` files, normalize filenames |

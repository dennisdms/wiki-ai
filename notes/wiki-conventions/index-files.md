# Index Files

Every directory in the wiki has an `_index.md`. It documents that folder's structure, acts as a local table of contents, and orients a reader who lands anywhere in the hierarchy.

## Template

```markdown
---
title: Topic Title
path: notes/topic/
---

# Topic Title

One or two sentences of hand-written context. What unifies these notes?
What questions does this cluster address?

## Contents


- [[note-slug]] — One sentence describing what this note covers.
- [[another-note]] — One sentence describing what this note covers.
- [[subtopic/_index]] — One sentence describing what this subdirectory contains.
```

## Frontmatter

- `title` — Title Case name for the directory topic.
- `path` — Directory path relative to the repo root, trailing slash included (e.g. `notes/game-mechanics/`). This tells a reader exactly where they are.

## What is hand-written vs. auto-generated

| Section | Who writes it |
|---|---|
| Frontmatter | Created by `index` skill on first run; left alone after |
| Narrative (above `## Contents`) | Written by the user or `research` skill; never overwritten |
| `## Contents` list | Fully regenerated by `index` skill on every run |

Do not hand-edit lines inside `## Contents` — they document the folder's direct children and will be overwritten the next time the `index` skill runs.

## Entry format

Every entry in `## Contents` must have a description:

```
- [[note-slug]] — One sentence describing what this covers.
- [[subdir/_index]] — One sentence describing what this directory contains.
```

Files and directories are listed together, sorted alphabetically. There are no bare links — every entry has a description. If none can be derived, the skill writes `— (no description yet)` as a placeholder.

**Where descriptions come from:**
- Notes: the `description` frontmatter field → first non-heading sentence of the body → `title` field.
- Directories: the first sentence of the subdirectory's hand-written narrative → `title` frontmatter.

## When indexes are regenerated

The `index` skill is called automatically by:

- `hierarchy` — after placing a note or creating a directory
- `research` — after saving a new or updated note
- `cleanup` — as part of a full wiki repair pass

Invoke directly: `/index notes/my-topic/`

## Special indexes

- `_index.md` (repo root) — hand-maintained overview of the whole project; `index` skill does not touch it.
- `notes/_index.md` — auto-maintained; lists all top-level topic directories.
- `reports/_index.md` — auto-maintained; lists all generated reports.
